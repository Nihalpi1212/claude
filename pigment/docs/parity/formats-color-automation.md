# Parity: File formats, colour management, metadata, printing, automation, video, cloud and AI

Part of [Pigment and Photoshop: feature parity](../PARITY.md), as of Pigment 0.3.1 (November 2026).

Pigment's file, colour and automation layer is solid for an 8-bit sRGB raster workflow (own .pigment container, PNG 8/16, PNG-8, JPEG, WebP, single-frame GIF, baseline TIFF 8/16/32, Targa, an Actions engine with Batch / Image Processor / Contact Sheet / Photomerge, and seven AI commands plus an assistant on the user's own OpenAI or Gemini key), but against Photoshop this area is the widest gap in the product. PSD interchange is shallow: lib/io.js keeps pixel layers, groups, raster masks, clipping, 15 adjustment kinds and single-style text, yet layer styles are dropped in both directions (the writer does not even bake them), fill / shape / smart-object layers are rasterised, guides, paths, alpha channels, ICC and 16/32-bit are lost, and CMYK / Lab / Duotone / Multichannel PSDs cannot be opened at all because ag-psd rejects those modes. There is no colour management whatsoever (no ICC read, kept, converted or embedded; no Color Settings, Assign / Convert to Profile or profile-based proofing; CMYK / Lab are views of RGBA), which also blocks print colour handling, real separations and spot colour; a CMM such as lcms2 (MIT) is the honest route, while Adobe ACE, Adobe's bundled profiles and Pantone books are not redistributable. Whole subsystems are absent: Timeline / video / frame animation (the GIF codec is multi-frame ready but nothing drives it), camera RAW, PDF / EPS / AI import, HDR formats (EXR, Radiance), HEIC / JPEG XL / JPEG 2000, a scripting API and plug-in host, .atn files, droplets, variables / data sets, Script Events Manager and Generator; metadata handling is limited to ten XMP fields written only into PSD, and saving strips EXIF, IPTC and resolution from JPEG / PNG. Honestly not buildable as Photoshop has them: Creative Cloud documents, Libraries, Adobe Fonts, Stock, Share for Review, Firefly models, Neural Filters' trained models, Adobe-signed Content Credentials, ExtendScript / UXP / 8bf compatibility and Adobe's camera and lens profiles; each has a stated substitute (local files, user-supplied data, open-source models, Pigment's own API). The cheapest high-value work is PSD fidelity through data ag-psd already exposes (effects, vector fills, guides, colour labels, PSB write), metadata pass-through, and small codecs through the existing registerOpenFormat / registerExportFormat registry.
