# Pigment and Photoshop: feature parity

This is the inventory of Adobe Photoshop's features and where Pigment 0.3.1 stands on each one (November 2026). It was produced by an audit: seven reviewers walked Photoshop's menus, tools, panels, dialogs, preferences and file formats, and checked each entry against Pigment's source code; a further pass looked for what they had left out. Statuses were judged by reading the code, not by running every feature, and the tables are regenerated by audit rather than by hand, so they can lag behind the code.

**Pigment 0.4** built the seventeen work packages planned for it (see "### 0.4" under "Planned releases"). The area pages still show each row's 0.3.1 status: every row whose "Planned" column reads "0.4 · *package*" (203 rows) is done in 0.4, except for the gaps named in the 0.4 table. The Summary has a second table that counts them that way.

**Statuses**

- **Done**: present, with the options a Photoshop user expects.
- **Partial**: present, but options or sub-features are missing (the entry says which).
- **Approximate**: present, built on a different algorithm or a simpler model than Photoshop's (the entry says how it differs).
- **Missing**: not there yet.
- **Not feasible**: cannot be built faithfully in a free offline application, because it depends on Adobe's servers, licensed data or proprietary trained models; the entry names the closest honest substitute where there is one.

"Effort" is a rough size for finishing an entry (S: under a day, M: a few days, L: a week or more, XL: a subsystem). "Planned" names the release and work package that covers it.

## Cannot be built faithfully

These depend on Adobe's services, licensed data or proprietary models. Where an honest substitute exists it is named, and planned like any other feature.

- New Document: templates from Adobe Stock: needs Adobe Stock servers and licensed template files; substitute: a local templates folder of .pigment / .psd files offered in the New Document dialog, built by home-new-doc-browser
- Open: HEIF/HEIC: HEVC is patent-encumbered, so no decoder can be bundled; substitute: decode through the operating system's codec (macOS ImageIO, Windows HEIF extension) or a user-installed libheif, built by formats-more-codecs
- Cloud documents (Save to Creative Cloud, PSDC, offline availability): Adobe's cloud storage and format; substitute: local .pigment files in any synced folder, nothing to build
- Invite to Edit / Share for Review: needs Adobe accounts and servers; substitute: the OS share sheet on an exported copy, built by file-handling-autosave
- Version History: tied to Adobe cloud documents; substitute: local numbered versions kept inside the .pigment file with a browse and restore panel, built by file-handling-autosave
- Search Adobe Stock: Adobe's commercial service and licensing; no substitute
- Image Processing (Select Subject and Remove Background on device or cloud, generative Remove tool, Firefly model choice): chooses between Adobe's device models and Adobe's cloud; substitute: the existing AI Accounts dialog plus the manager for downloadable open models, built by local-models-segmentation
- Duotone / spot ink colour books (Pantone, Toyo, DIC...): licensed data; substitute: free RGB / Lab inks (present today) plus import of user-supplied .acb / .ase books, built by color-picker-swatches
- Image Size: Preserve Details 2.0: Adobe's trained upscaler; substitute: an open super-resolution model the user downloads, offered as a labelled resample choice by neural-filters-local
- Mask All Objects: Adobe's object-detection model; substitute: an open segmentation model making one masked group per object, built by local-models-segmentation
- Relink to Library Graphic: needs Creative Cloud Libraries; substitute: Relink to File, built by linked-smart-objects
- More from Adobe Fonts: Adobe's font service and licence; substitute: Add Fonts (user .ttf / .otf / .woff2 files in a Pigment fonts folder), built by type-fonts
- Match Font: Adobe's recognition model and the Adobe Fonts catalogue; substitute: Identify Font, which asks the user's own OpenAI / Gemini key for candidates and matches them to installed fonts, built by generative-features
- Show Similar Fonts: Adobe's visual-similarity model; substitute: similarity from PANOSE / OS-2 metrics and measured glyph proportions of installed fonts, built by type-fonts
- Adobe Fonts filter, activation and automatic activation of missing fonts: Adobe's cloud subscription service; substitute: user-supplied font files and a clear missing-font dialog, built by type-fonts
- Fonts bundled with the application: Adobe's commercial families cannot be shipped; substitute: bundled OFL families (Source Sans / Serif, Noto, Noto Color Emoji) as guaranteed defaults, built by type-fonts
- Neural Filters: Skin Smoothing: Adobe's proprietary model; substitute: open face detection plus frequency-separation smoothing inside the face mask, built by neural-filters-local
- Neural Filters: Smart Portrait: runs on Adobe's cloud GAN; substitute: a labelled generative edit through the user's own provider key inside the Neural Filters workspace, built by neural-filters-local
- Neural Filters: Makeup Transfer: proprietary model; substitute: a provider image edit with a reference image (or an open model the user downloads), built by neural-filters-local
- Neural Filters: Landscape Mixer: Adobe cloud model; substitute: a provider image edit with a reference image through the user's key, built by neural-filters-local
- Neural Filters: Style Transfer: Adobe's styles and model; substitute: an open arbitrary style-transfer model with user-supplied style images, built by neural-filters-local
- Neural Filters: Harmonization: proprietary model; substitute: statistics-based Match to Layer on the Match Color engine, built by neural-filters-local together with Harmonize
- Neural Filters: Colorize: proprietary model; substitute: an open colourisation model the user downloads, or a provider request, built by neural-filters-local
- Neural Filters: Super Zoom: proprietary model; substitute: an open super-resolution model, built by neural-filters-local
- Neural Filters: Depth Blur: proprietary depth model; substitute: an open monocular depth model feeding the existing Lens Blur depth-map input, built by neural-filters-local
- Neural Filters: JPEG Artifacts Removal: proprietary model; substitute: classical deblocking (shared with Reduce Noise in filter-dialogs-a) or an open model, built by neural-filters-local
- Neural Filters: Photo Restoration: proprietary model; substitute: open restoration models where their licences allow plus classical scratch inpainting, built by neural-filters-local
- Camera Raw: Profiles and profile browser: Adobe's profiles are licensed data; substitute: a profile slot that loads user .cube LUTs and Pigment's own looks, built by camera-raw-workspace
- Camera Raw: Denoise (AI), Raw Details, Super Resolution: Adobe models working on raw mosaics; substitute: open denoise and super-resolution models on RGB, offered through neural-filters-local
- Camera Raw: Optics profile corrections: Adobe lens profiles are licensed data; substitute: the open Lensfun database matched by EXIF, built by lens-correction-profiles
- Camera Raw: Lens Blur: Adobe's depth model; substitute: an open depth model feeding Pigment's Lens Blur, built by neural-filters-local
- Camera Raw: Masking (AI: Subject, Sky, Background, Objects, People, Depth Range): Adobe models; substitute: Subject, Sky and object masks from the open models of local-models-segmentation, plugged into the mask-source registry of camera-raw-local and labelled as such
- Lens Correction: Auto Correction lens profiles: Adobe's profile database is licensed; substitute: the Lensfun database matched by EXIF plus user .lcp files, built by lens-correction-profiles
- Object Finder (hover preview, Show All Objects, overlay colour/opacity, refresh): Adobe's proprietary detector; substitute: an open segmentation model that pre-computes object masks for hover, built by local-models-segmentation
- Remove tool: Adobe's trained inpainting model and Firefly; substitute: the same brush-then-fill tool on Content-Aware Fill, with an open inpainting model or the user's provider as options, built by retouch-healing
- Adobe's bundled and downloadable brush libraries: licensed content served by Adobe; substitute: Pigment's own presets and user-supplied .abr files, built by brush-settings-panel
- Color Picker: Color Libraries: the books are licensed data; substitute: user-loaded .acb / .ase / .aco libraries and freely licensed sets, built by color-picker-swatches
- Comments panel (Share for Review comments on cloud documents): needs Adobe's cloud review service; substitute: local Notes stored in the document, built by notes-count-measurement
- Libraries panel (Creative Cloud Libraries, synced assets, Adobe Stock search): Adobe cloud service and Stock catalogue; substitute: a local library folder shown in the built-in browser (home-new-doc-browser) and shareable preset sets (preset-files-manager)
- Version History panel (cloud document versions: name, bookmark, revert, open): tied to Adobe cloud documents; substitute: the local versions panel built by file-handling-autosave
- Content Credentials panel (C2PA: enable per document, edits and activity, attach on export, publish to cloud, connected accounts): needs an Adobe-issued certificate, the trust list and cloud publishing; substitute: reading and showing existing manifests with the open c2pa library, built by file-info-dialog
- Discover / Learn: hands-on tutorials, quick actions, What's New: Adobe-hosted content; substitute: Pigment's bundled offline guide and walkthroughs, built by status-bar-help
- Plugins: UXP plugins panel, Plugins menu, legacy Extensions (CEP), 8BF filter plug-ins: Adobe's proprietary hosts and native binaries cannot be run; substitute: Pigment's own JavaScript plug-in API and manager, built by plugin-api
- Home screen: cloud tabs (Your files, Shared with you, Lightroom photos, Deleted): Adobe cloud storage and Lightroom sync; no substitute needed beyond local recent files (home-new-doc-browser)
- Share button, Share for Review, Invite to Edit, quick share: Adobe cloud review and collaboration; substitute: OS share sheet and export-and-reveal, built by file-handling-autosave
- Generic EPS / PostScript rasterised on open: needs a PostScript interpreter, and Ghostscript (AGPL) cannot be bundled; substitute: detect and call a user-installed Ghostscript, otherwise say so, built by formats-more-codecs
- HEIF / HEIC: HEVC patents rule out a bundled decoder; substitute: the operating system's codec from the main process where present, built by formats-more-codecs
- Adobe camera matching profiles and Adobe Standard colour for RAW: proprietary per-camera data; substitute: DNG-embedded and LibRaw colour matrices plus user-supplied .dcp profiles, built by raw-open-workflow
- Substance materials (.sbsar) and 3D model formats (OBJ, glTF, USD, STL, DAE, KMZ, U3D): no 3D engine in Pigment and Substance is proprietary; substitute: OBJ / glTF / STL import into the rendered 3D object layer of 3d-lite; none for .sbsar
- Adobe (ACE) colour engine: Adobe's proprietary CMM; substitute: LittleCMS 2 (small differences in out-of-gamut colours), built by icc-engine
- Adobe's bundled ICC profiles (Adobe RGB (1998), ProPhoto RGB, U.S. Web Coated (SWOP) v2, Coated FOGRA39, GRACoL, Japan Color): Adobe's licence forbids shipping them; substitute: generated sRGB, Display P3, Adobe-RGB-compatible and ProPhoto-compatible profiles, the operating system's profiles and user .icc files (ECI and FOGRA publish free press profiles), built by icc-engine
- Color Libraries: PANTONE books: licensed data; substitute: user-supplied .acb / .ase files, built by color-picker-swatches
- Content Credentials: attach signed credentials on export: trusted status needs Adobe's certificate on the C2PA trust list; substitute: none planned beyond reading credentials (file-info-dialog); a manifest signed with a user-supplied certificate would show as an unrecognised signer
- Adobe lens profiles (LCP database): proprietary data; substitute: Lensfun data and user-supplied .lcp files, built by lens-correction-profiles
- ExtendScript / UXP / Action Manager (batchPlay) compatibility: Photoshop's DOM, event IDs and runtimes are Adobe's; substitute: Pigment's own scripting API with a partial app.activeDocument-style shim, built by scripting-api
- Filter plug-ins (.8bf) and other Photoshop SDK plug-ins (file format 8bi, automation 8li, export, acquire): native binaries against Adobe's SDK cannot be loaded; substitute: the Pigment plug-in API on the filter, adjustment and format registries, built by plugin-api
- Plug-in panels and marketplace (UXP plug-ins, legacy CEP extensions, Plugins panel, Browse Plugins): Adobe platforms and marketplace; substitute: local ES-module plug-in folders with a manifest and a manager dialog, built by plugin-api
- 3D menu, 3D panel, 3D layers, extrusions, materials, lights, ray-trace render, 3D printing: retired by Adobe, and a faithful 3D layer system is a separate product; substitute: the rendered 3D object layer of 3d-lite and the existing 2D perspective tools
- Substance 3D materials and Substance 3D Viewer round trip: proprietary Adobe engine and app hand-off; substitute: the existing procedural textures and user image patterns, nothing further to build
- Creative Cloud documents (.psdc), offline sync, Manage Cloud Documents: Adobe's storage service and format; substitute: local files in any synced folder, nothing to build
- Creative Cloud Libraries: Adobe service; substitute: a local library folder in the built-in browser (home-new-doc-browser) and shareable preset sets (preset-files-manager)
- Adobe Fonts (activation, missing-font resolution): licensed font service; substitute: system fonts, user font files and a missing-font report, built by type-fonts
- Adobe Stock (search, license, licensed previews): commercial Adobe service; no substitute (File > Place for images the user obtains)
- Share for Review, Invite to Edit, live co-editing, Comments panel: need Adobe's servers and accounts; substitute: an exported copy plus local notes, built by notes-count-measurement
- Adobe Bridge integration (Browse in Bridge, Mini Bridge, batch from Bridge): Bridge is a separate Adobe application; substitute: a built-in folder and thumbnail browser with ratings and keywords that also feeds Batch, built by home-new-doc-browser
- Lightroom integration (Edit in Photoshop round trip, Lightroom photos on the Home screen): Adobe ecosystem; substitute: Pigment already works as an external editor (opens and saves TIFF / PSD in place), nothing to build
- Preset and settings sync, Home screen learn content, in-app Discover search: Adobe account services; substitute: export and import of all presets and settings as one file (preset-files-manager) and the bundled offline guide (status-bar-help)
- Adobe Firefly models and generative credits: Adobe's hosted model; substitute already in place: the user's own OpenAI or Gemini account, with more providers added by generative-features
- Neural Filters: portrait (Skin Smoothing, Smart Portrait, Makeup Transfer): Adobe's trained models, some cloud-run; substitute: classical skin smoothing and labelled provider edits in the workspace built by neural-filters-local
- Neural Filters: creative (Landscape Mixer, Style Transfer): Adobe models and preset style images; substitute: provider edits with a reference image and an open style-transfer model, built by neural-filters-local
- Neural Filters: colour (Harmonization, Color Transfer, Colorize): Adobe models; substitute: statistics-based colour transfer and harmonisation plus an open colourisation model, built by neural-filters-local
- Neural Filters: photography and restoration (Super Zoom, Depth Blur, JPEG Artifacts Removal, Photo Restoration): Adobe models; substitute: open depth, super-resolution, deblocking and restoration models, built by neural-filters-local
- Camera Raw AI features (Denoise, Super Resolution, Raw Details, AI masks, Generative Remove, Lens Blur, reflection removal): Adobe models inside Camera Raw; substitute: open models from local-models-segmentation and neural-filters-local as mask, denoise and depth sources for camera-raw-local
- Content Credentials on AI-generated content: depends on Adobe-signed C2PA manifests; substitute: an XMP DigitalSourceType note naming the provider, written on export, built by generative-features

## Accepted approximations

Built on a different algorithm than Photoshop's, with results a user would not tell apart; no further work is planned on these.

- Auto Color: different maths (per-channel stretch and gamma towards a common mean) with results close to Photoshop's on ordinary photos; the controls a user would miss are the separate Auto Color Correction Options entry (adjust-tonal)
- Focus Area: parameters and output: every Photoshop control is present on Pigment's own in-focus estimator and the output choices match; the missing brushes and view modes are separate entries (select-menu-finish)
- Sharpen: Shake Reduction: single-trace deconvolution covers the common straight-shake case, and Adobe has removed this filter from current Photoshop, so no further work is planned
- Actions: Save Actions / Load Actions: Pigment's own .pigment-actions files do the same job; exchange with Photoshop is the separate .atn entry (actions-atn)
- Photomerge: own registration and blending with all six layouts, vignette and distortion correction and content-aware fill; results match on ordinary overlapping photos
- Generate Background: the same flow through the user's own provider instead of Firefly; lighting match depends on the chosen model, as it does in Photoshop

## Planned releases

Everything that is missing or partial is grouped into work packages, each a subsystem one engineer can build, ordered into releases. Foundations and what a Photoshop user reaches for daily come first.

### Why this order

Scope. The inventory has 1,149 rows: 1,126 distinct names plus 10 leftovers (13 names occur in two areas and are listed once). 1,055 go into 110 packages over eight releases (0.4 to 0.11), 6 approximations are accepted and 75 are not feasible. Every one of the 1,136 strings is in exactly one place; this was checked by script against the inventory before writing the answer, as was the rule that no package depends on a later release or on a same-release package other than the release skeleton. Order. 0.4 and 0.5 hold what a Photoshop user reaches for daily. 0.4: type engine with Character and Paragraph panels, layer-style depth, adjustment-dialog depth, gradients, patterns, guides and snapping, vector masks, live shapes, Layers panel and Layer menu depth, Photoshop's default shortcuts. 0.5: brush engine, ICC engine, PSD layer and text fidelity, Camera Raw depth, preset panels and files, colour UI, font menu, Type menu commands, shortcut editor. 0.6: selection, channels, smart filters, colour settings and proofing, metadata, PSD document resources, export and save options, RAW opening, PDF import, view navigation, autosave. 0.7: pen and paths, transforms, retouch tools, content-aware fill, filters, Liquify, linked smart objects, PDF export, vector exchange. 0.8: workspace (docking, windows, preferences, context menus), print, actions, scripting, layer comps, healing. 0.9: artboards, notes and measurement, more codecs, lens profiles, international type, 16/32-bit pipeline, local model runtime, frame animation, plug-ins, variables. 0.10 and 0.11: slices, HDR, real CMYK, neural-filter substitutes, generative depth, video, tiles, scratch, GPU, accessibility and languages, 3D. Skeletons. Shared plumbing is either a package in an earlier release (icc-engine, brush-engine-core, frame-animation, local-models-segmentation, scripting-api, tile-store, pdf-export, history-panel-depth) or sits in the release skeleton. skeleton-04 and skeleton-05 are packages because they carry real contracts: preset store, rich-text model and layout facade, document-level store (guides, comps, slices, notes, counts, artboards), vector-mask and blending fields, snap hook, shared gradient / pattern / contour field types, session registry (0.4); BrushPreset schema, PSD mapper registries, container-chunk hooks for ICC and metadata, Camera Raw tab registry, keymap store, preset-format registry (0.5). They land before the parallel round, as in 0.2 and 0.3. Later releases need only the usual integrator step (menu and keymap entries, stub modules, MODULES list), except where a package note asks for more: deep-pipeline, tile-store and accessibility-i18n-input each need a short skeleton step of their own. Things the owner should know. 1. Same-release pairs that meet only at integration: the four type packages in 0.4 build against the facade and a stub engine; layer effects use the gradient and pattern field types that the gradients and patterns packages fill; brush engine and Brush Settings panel share the preset schema. Plan integration time for these three. 2. Sizes. Packages marked XL will press against the 4,000-line limit: type-engine-core, layer-style-effects, brush-engine-core, raw-open-workflow, camera-raw-local, panel-docking, document-windows, artboards-frames, type-international, deep-pipeline, local-models-segmentation, hdr-32bit, cmyk-lab-storage, neural-filters-local, video packages, tile-store, gpu-pipeline, 3d-lite. Notes say where a second sitting is likely. tile-store and cmyk-lab-storage are not registration-point changes: they replace the 'one RGBA canvas per layer' assumption and are the main schedule risk. 3. Small packages by entry count (psd-text, pdf-import, camera-raw-local, plugin-api, workers-progress, tile-store, vanishing-point, gpu-pipeline) are whole subsystems that the audit described in two to four rows. 4. Multi-part entries are assigned to the package that finishes the last part, and a few are completed across packages; the package notes name the other half (for example the autosave entries: recovery in file-handling-autosave, non-blocking save in workers-progress; preset file formats: .abr and .atn register from their own packages; status-bar readouts that depend on scratch and measurement scale). 5. Third-party code to vet before bundling: HarfBuzz (MIT), LittleCMS 2 (MIT), pdf.js (Apache-2.0), LibRaw (LGPL / CDDL), OpenJPEG, libjxl, libavif (BSD), onnxruntime-web (MIT), three.js (MIT), Hunspell dictionaries and TeX hyphenation patterns (licence per language), Lensfun data (LGPL, user-downloaded), OFL fonts. Ghostscript (AGPL) and HEVC decoders are never bundled. Wasm needs a CSP change (wasm-unsafe-eval); video and audio need media-src; model and Lensfun downloads need network allowances. Installer size will grow noticeably with fonts, HarfBuzz, lcms2 and pdf.js in 0.4 to 0.6. 6. Behaviour changes that need release notes: Ctrl+F, Ctrl+Y, Alt+Ctrl+Z, Ctrl+2 and the export keys move to Photoshop's meanings in 0.4 and 0.6; untagged files stay sRGB but tagged files stop being converted on open in 0.5; 32-bit documents become scene-linear in 0.10. 7. Not verified here: nothing was run; splits were judged from ARCHITECTURE.md, the audit text and file sizes. The Dynamic Text entry comes from the critic's memory and should be confirmed before it is built. 3D is planned as an honest substitute in the last release because Adobe has retired it; dropping it is a reasonable owner decision. 8. Accepted approximations are limited to six where a user would not tell the difference or Adobe has dropped the feature; every other 'approx' row is in a package, usually because the audit said a user would notice.
